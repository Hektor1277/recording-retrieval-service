# 关键决策

## 仓库与目录
- 父仓库只保留协议与背景文档。
- 真正实现长期放在 `tools/recording-retrieval-service/app/` 独立仓库。

## 优先级
- 资源链接命中率高于字段完整度。
- 在搜索阶段，`streaming`（资源平台）优先级高于 `fallback`（搜索引擎兜底）。
- 对外协议稳定高于内部模型美观；能不改协议就不改协议。

## LLM 使用策略
- 文本分析与普通归并优先走 `fast model`（快速模型）。
- 仅在候选数较多、前两名分差小、且确实存在模糊决策时，才升级到 `reasoning model`（推理模型）。
- 当前 `deepseek-reasoner` 较慢，不适合所有实时路径。

## 搜索与采纳策略
- 非中文网站不能使用中文关键词作为主查询。
- 中文平台目前重点支持 `bilibili`。
- 协作型体裁优先保留“人物组合查询词”。
- 若用户未提供年份且存在接近并列的高分链接，可以保留更多正式资源链接，避免过早单选。
- 若已有强资源候选，应尽量少跑低收益阶段。

## 当前已知有效的评分修正
- 角色感知 `lead slots`（主参与者槽位）已接入同版打分。
- 乐团缩写扩展已接入查询构造。
- 多作品合辑和单乐章条目会被显著降分。
- 只给单一人物的室内乐条目仍然会偏向单人版本，需要继续优化。
